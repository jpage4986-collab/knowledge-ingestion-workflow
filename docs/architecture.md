# 架构与数据流

## 一句话结构

来源连接器负责发现与读取，解析器把原件转换成可定位的页面内容，审查器对带证据的候选事实作准入判定，发布器只把通过门禁的文档送入对应知识库，索引与评测器负责追踪、验证和迭代。

## 阶段与状态

| 阶段 | 输入 | 关键检查 | 失败去向 |
|---|---|---|---|
| 发现 | Zotero 条目、开放文献接口、用户指定来源 | 主题匹配、DOI/哈希去重、可访问性 | 筛除或等待补充元数据 |
| 原件获取 | 通过筛选的候选 | 文件类型、大小、哈希、许可/开放获取状态 | 下载失败队列；不绕过付费墙 |
| 解析 | 原始 PDF | 页数/空页/文本与图表覆盖、MinerU 退出码 | 解析失败或待复核 |
| 抽取与审查 | MinerU 页面文本、领域字段定义 | 每个重要字段绑定页码与原文证据；检查冲突与缺失 | 隔离区，不上传 |
| 路由与发布 | 通过审查的原件及元数据 | 知识域到 RAGFlow dataset 映射；API 返回与状态检查 | 有界重试，记录远端 ID |
| 解析后校验 | RAGFlow 文档 | 解析器、完成状态、分块数、零分块/重复项 | 修复队列或保留旧版本 |
| 检索评测 | 标注查询、期望证据 | 命中率、证据覆盖、出处准确、拒答表现 | 分析失败类型再调参 |

状态记录宜按文档身份、SHA-256、来源 ID、解析版本、审查判定、数据集 ID、远端文档 ID 和每次重试的时间/结果建立关联。原件不可由摘要覆盖；重跑解析应产生可比较的新版本。

## 质量闸门

1. **来源闸门：**来源类别与链接可核验；不能只凭模型生成的权威性判断来源。
2. **解析闸门：**页数、正文、表格/图像和关键结构没有明显丢失；解析异常不进入自动发布。
3. **证据闸门：**结构化事实必须能回指页码和原文；数字/单位/条件冲突时保留冲突，不猜测补齐。
4. **准入闸门：**相关性和质量阈值按知识域配置。模型判定与规则检查分开留痕，低置信或缺证据即隔离。
5. **入库后闸门：**确认远端解析结束、分块非空，并用检索测试确认可被正确召回。

## 自动迭代

评测应将解析、抽取、路由、分块和检索错误分开记录。每次调节只改变少数变量，在固定的验证集上比较，并保留当前通过的版本；不得用同一批数据既调参又宣称独立验收。离线结构检查是必要条件，不等于领域事实已达到某个绝对准确率。
